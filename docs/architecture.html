com.nch.todoapp

ToDoApp Architecture

Jetpack Compose todo app with Hilt DI, Room cache, pluggable remote API, and Firebase Auth (Google / guest). Graphs below map layers, navigation, and data flow.

1. Layer overview

UI talks only to ViewModels → TodoManager. Auth and data backends are injectable interfaces.

2. Navigation flow

Start at List if signed in, else Login. Auth state clears the back stack between Login ↔ List.

3. Data sync flow

Remote is source of truth on success. Room is the offline cache / fallback when fetch fails. Today DI binds LocalFileApiService (JSON per user); Firestore impl is swap-ready. 

flowchart TB
  VM["Feature ViewModels"]
  TM["TodoManager"]
  REM["ApiService
LocalFileApiService ★"]
  LOC["LocalRepService → Room"]
  STATE["todoItemsState
StateFlow"]

  VM -->|"sync / CRUD"| TM
  TM -->|"1. remote first"| REM
  TM -->|"2. on success: update cache"| LOC
  TM -->|"3. emit list"| STATE
  STATE -->|"collect"| VM
  REM -.->|"fetch fail → keep Room"| LOC
